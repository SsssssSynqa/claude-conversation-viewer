# 项目纠正记录

## 5. 统计页不是独立海报，全站必须共享一套设计系统（2026-08-12）

**纠正**：前四轮主要重绘统计页，导致统计区逐渐形成独立字体、表面和阴影，而侧边栏、
搜索、导出、会话仍使用旧的新拟态。Synqa 明确要求“不只是统计总览，侧边栏和别的页面
也要统一”，并要求三张图表提供具体数据交互。

**规则**：

> 1. 页面级 UI 重构必须先建立全站 semantic tokens、type roles 和 elevation grammar，再进入
>    单页组件；不得让一个页面通过私有 token 演变成第二套设计系统。
> 2. “可交互图表”必须包含 pointer、click/tap、keyboard、tooltip、完整数据语义和 resize，
>    不能把原生 `title` 或静态 `aria-label` 当成交互完成。
> 3. 全站验收至少覆盖上传、导航、搜索、导出、会话、设置、统计与移动端；只截统计长图
>    不能证明界面已经统一。


## 1. 主题语言与具体组件要分层锁定（2026-08-12）

**纠正**：第一版需求简报把亮/暗新拟态整体当成必须原样保留，Synqa 随后明确：
新拟态方向要保留，但其 surface、边框和阴影本身可以重做；真正锁定的是 Claude
伪官端边框，以及亮/暗主题里已经改好的两个百分比环。

**规则**：

> 1. “保留某种主题”不等于冻结这个主题的所有实现细节，要继续确认具体锁定到
>    token、容器、组件还是数据图形。
> 2. 开工前把不可改项写到组件级：本轮是 Claude 卡片边框与两个百分比环；其余
>    新拟态 surface 可以在同一设计语言内优化。
> 3. 每批 diff 后单独搜索 `.stats-ring` 和 Claude theme shadow/border，确认没有被
>    范围更大的 CSS override 误伤。

## 2. Token 调色与细节抛光不能冒充视觉重构（2026-08-12）

**纠正**：第一轮虽然更换了统计色、阴影、间距和部分图表样式，但仍沿用原有四列卡片、
相近的系统无衬线数字和相同的信息构图。Synqa 的实际观感是“没看出变化，像只换了颜色”，
说明改动只在实现层显著，在视觉层没有建立新的识别度。

**规则**：

> 1. 用户要求“完善 UI / 不好看”且明确点名字体时，验收必须包括第一眼可感知的字形差异、
>    数字尺度差异和构图差异，不能只报告 token、阴影参数或代码行数。
> 2. 新字体若回退后与原字体近似，就等于没改。必须用可稳定加载的字体资产或明显不同的
>    字体类别，并用浏览器 computed font / 截图确认真实生效。
> 3. 在宣布完成前做旧版与新版并排对照；若缩略图轮廓仍基本一致，继续重构，不得把微调
>    描述成重新设计。

## 3. 新拟态不等于给卡片再塞一个凹槽（2026-08-12）

**纠正**：第二版为了强调数字牌面，在每张指标卡内部又放了一个带阴影的数字槽，形成
明显的“框套框”；亮色材质仍有灰褐浑浊感，而每日活跃和每月字数仍保留旧图形骨架。

**规则**：

> 1. 用户明确反感嵌套容器时，先删层级，不用换一种阴影继续包装同一层级。
> 2. 新拟态深度优先由同一表面的明暗和空间关系表达，不默认使用“外凸卡片 + 内凹框”。
> 3. 用户逐项点名旧图表不好看时，必须更换图形语法：色块不能只改圆角，槽柱不能只改
>    宽度；缩略图轮廓需要发生可识别变化。

## 4. 新拟态的深度必须有清晰光源和近边对比（2026-08-12）

**纠正**：第三版虽然清理了综合色，但亮色卡片仍使用范围过大、对比过低的双向模糊阴影，
边缘像融进背景，缺少“从底板凸出来”的实体感；每日活跃仍是常规竖柱，只是排列更连续。

**规则**：

> 1. 检查新拟态时不能只看颜色干不干净，还要检查卡片边缘 1—8px 范围内是否存在明确的
>    高光、背光侧暗边与投影落点；大 blur 只负责空气感，不能承担轮廓定义。
> 2. 当用户连续两次退回同一图表，不再在同一笛卡尔柱形骨架上修饰，改用与数据语义相符
>    的新结构。本轮 24 小时时段使用放射时钟，让周期本身成为图形。
> 3. 用户指定某个数据组件的品牌色时，整套强度阶必须从该色系生成；空值可以保持中性，
>    有值层级不得混入另一套主色。
